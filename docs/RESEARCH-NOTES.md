This file records **our own conclusions** from primary-source research conducted on **2026-09-05**, with links to the official sources. Raw documentation and whitepapers are intentionally **not committed** to this repository — several sources carry third-party copyright and custom licenses (see the licensing note below), and the originals are publicly accessible at the links provided. ## 1inch Aqua / SwapVM

- **No Base Sepolia deployment.** We verified via RPC that both canonical addresses hold no bytecode on Base Sepolia (`eth_getCode` → `0x`), while Base mainnet has both contracts live (registry deployed at block ~48,839,900). This drove our decision to self-deploy the official contracts from source to Base Sepolia. Sources: [official contract addresses docs](https://business.1inch.com/portal/documentation/aqua/contract-addresses), our own RPC checks.
- **Canonical addresses (identical across 13 production chains):** Aqua registry `0x1111113ccf1426a8e30e2bff5e005d929bf6a90a`; AquaSwapVMRouter `0x111111338c5091e8440b67b168bae16a668ac0de`.
- **Pin git tag `v1.0.2` of [1inch/swap-vm](https://github.com/1inch/swap-vm)** — the `main` branch is an undeployed refactor with different signatures (per the official [SwapVM FAQ](https://business.1inch.com/portal/documentation/aqua/help/swapvm-faq)).
- **The official price surface is `AquaSwapVMRouter.quote(...)`** (static-call semantics, executes the same program as `swap`). There is **no separate Lens/Quoter contract** — this corrected an early assumption in our spec. Source: [SwapVM FAQ](https://business.1inch.com/portal/documentation/aqua/help/swapvm-faq) + router ABI.
- **1inch's own shipped strategies embed a KYC gate** (an opcode keyed on a soulbound KycNFT held by KYB-approved resolvers). The documented permissionless path is to ship your own strategies without that instruction — the [official strategy template](https://business.1inch.com/portal/documentation/aqua/getting-started/strategy-template) states it directly, and contract-taker fills are supported.
- **Aqua mechanics:** makers `ship` virtual balances (tokens never leave the maker wallet until a fill pulls/pushes); the taker path is approve + `router.swap(...)` which pulls and pushes atomically. Virtual balances are commitments, not escrow — total shipped must stay ≤ the maker's real balance. Sources: [Aqua whitepaper](https://github.com/1inch/aqua/blob/main/docs/whitepaper-aqua-1.0.pdf), [SwapVM whitepaper](https://github.com/1inch/swap-vm/blob/release/1.1/docs/whitepaper-swap-vm-1.0.pdf), [liquidity-layer docs](https://business.1inch.com/portal/documentation/aqua).
- **Build requirements for the official contracts:** solc 0.8.30, `via_ir = true`, EVM target `cancun` (transient-storage reentrancy locks; the function-pointer opcode table requires IR codegen). Source: [1inch/swap-vm-template](https://github.com/1inch/swap-vm-template).
- **SDKs:** `@1inch/aqua-sdk` 0.3.0 (registry interactions: ship/dock/hash) and `@1inch/swap-vm-sdk` 0.4.0 (quote/swap/order/program builders), from the [1inch/sdks](https://github.com/1inch/sdks) monorepo. Footgun we noted: the hand-maintained TypeScript opcode enum is shifted relative to on-chain indices — programs must be composed via `AquaProgramBuilder`, which resolves opcodes correctly.
- **Licensing caution:** the Aqua/SwapVM repos use a custom source-available license (`LicenseRef-Degensoft-Aqua-Source-1.1` / `SwapVM-1.1`), not MIT/Apache. We therefore link to official material rather than redistributing it in this repo; our integration path (using and redeploying the official contracts) is explicitly permitted by the 1inch prize terms.

## Privy

- **Aggregations (cumulative spend caps) are tracked at sign level only.** They apply to `eth_signTransaction` / `eth_signUserOperation`; `eth_sendTransaction` spend is invisible to them. Rolling windows of 1h–72h only; max 10 aggregations per app; creation is currently REST-only; and the docs themselves frame them as "disaster prevention, not strict real-time enforcement". This drove our keeper design (sign via Privy, self-broadcast) and our framing rule that the on-chain contract — not Privy — enforces the total budget. Sources: [stateful policies](https://docs.privy.io/controls/policies/stateful-policies), [stateful policies recipe](https://docs.privy.io/recipes/using-stateful-policies).
- **Session signer flow** (app executes on behalf of a user's embedded wallet while the user is offline): app authorization key (P-256) → registered as a 1-of-1 key quorum → policy attached when the user consents via `addSigners` on the frontend → server signs requests with the authorization key. Revocation from the React SDK removes all signers (all-or-nothing on web). Sources: [user-and-server signers recipe](https://docs.privy.io/recipes/wallets/user-and-server-signers), [signers overview](https://docs.privy.io/wallets/using-wallets/signers/overview), [remove signers](https://docs.privy.io/wallets/using-wallets/signers/remove-signers).
- **Docs drift we noticed (2026-09-05):** some pages reference `addSessionSigner` (the real API is `addSigners`); the canonical client style is `privy.policies().create(...)`; the docs' example link `session-signers.tsx` now resolves to `signers.tsx`. Worth pinning exact SDK versions and re-checking the changelog before the demo.

## The Graph

- **Subgraph Studio supports Base Sepolia** (`network: base-sepolia`). Operational limits: 3 deployed subgraphs per account; **a redeploy auto-archives the previous version** (pin the versioned query URL); the dev endpoint is rate-limited (~3,000 queries/day); an API key is required to query. Source: [supported networks](https://thegraph.com/docs/en/supported-networks/), [Studio docs](https://thegraph.com/docs/en/subgraphs/quick-start/).
- **Mappings run on events/blocks only — there is no "now" at query time.** Consequence for Slope: BenchmarkComparison is stored as an as-of-last-fill snapshot computed in the mapping; the live planned-vs-actual curves are computed in the frontend from position parameters plus fill records. Source: [AssemblyScript mappings docs](https://thegraph.com/docs/en/subgraphs/quick-start/).
